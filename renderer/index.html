Connect Joggl to Jira

Joggl logs your time straight onto Jira Cloud issues. It needs your Jira site, the email address on your Atlassian account, and an API token. Nothing is sent anywhere else, and the token is encrypted by Windows before it is stored.

The address you use to open Jira in your browser.
Create one at id.atlassian.com/manage-profile/security/api-tokens — click Create API token, give it any label, then copy the value. It is shown only once.

How Joggl works

Joggl tracks your time on a timeline and writes it to Jira as worklogs. Nothing reaches Jira until you press Sync, so you can move blocks about all day and correct them before anyone sees them.

Putting time on a day
  • Run a timer. Click an issue in the list, or type in the box at the top and press Enter. Click the button again to stop. A timer runs only on today.
  • Drag an issue onto the day view. It becomes a half-hour block you can then move and resize. This is how you book time you have already worked, or a meeting that is still in the diary.
  • Click an empty hour on the day view and name the task there.
  • Drag the edges of a block to change its start or end, or drag the whole block to move it. Everything snaps to the quarter hour.
  • Type an exact time in the start, end or duration field of a row in On this day — the other two follow.
  • Copy previous day. Fills the day from the last one that has anything on it — over a weekend, or back past a holiday, up to 30 days. Time logged in the Jira web UI is copied too, and everything arrives unsynced. Clear day beside it empties the day; it never deletes anything from Jira.
Changing an entry
  • Click a block or a row to select it. The same entry lights up in both panels, which is how you tell which block is which row.
  • Double-click the task name to book the block against a different issue, keeping its times. Double-click anywhere else to write the Work description — the comment Jira shows beside the worklog.
  • Right-click for everything at once: edit the task, the work description, restart the timer on it, duplicate it, split it in half, or delete it.
Getting it into Jira
  • Sync sends every pending entry for the day. The button says how many and how long before you press it, and greys out when there is nothing to send. On any day but today it reads Re-sync and sends only what is not already there.
  • ● pending is waiting to be sent. ✓ synced is in Jira. ◇ local has no issue attached, so it counts towards your day's total but is never sent. ✗ error failed, and says why — nothing is ever logged twice.
  • Editing an entry that is already synced turns it back to pending, and the next Sync rewrites that worklog rather than adding a second one.
  • Rows labelled Manual Jira entry were booked in the Jira web interface, not here. They are shown so the day's total is honest, and they are read-only — change them in Jira.
Seeing the week
  • Week View in the sidebar shows Monday to Friday side by side — 7 adds the weekend, and a Saturday or Sunday with time on it is shown either way, because time you cannot see is time that never gets synced.
  • Every column does what the day view does: click an empty hour, drag and resize blocks, right-click for the menu. Drag a block sideways to move it to another day.
  • Sync week sends every pending entry across the columns shown, and says how many before you press it. ⋯ on a column head copies into that day, empties it, or empties the week — none of which deletes anything from Jira.
